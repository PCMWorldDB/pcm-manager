## Overview

Roles are permission bundles. A user can have more than one role, and their access is the combined set of permissions from all assigned roles.

Superadmin users have full access and are not limited by normal role permissions.

## Where Roles Are Managed

1. Open Settings, then select Users & Roles.
2. Use the Users table to open a user record.
3. Use the Roles table to inspect a role, its permissions, and the users who currently have that role.

## How Permissions Work

Each role can grant actions on one or more resources. A resource usually maps to an area of the app, such as Stats Editor, Releases, Integrations, or Admin tools.

Common action types include:

- Read or view access for opening an area.
- Create access for making new records.
- Update access for saving edits.
- Approve access for validation and approval workflows.
- Publish or download access for release and integration workflows.

> If a user can see a page but cannot perform an action, check whether their role has the specific action required for that workflow.

## Applying a Role to a User

1. Open Settings, then select Users & Roles.
2. Select the user from the Users table.
3. In the Roles panel, choose a role from the dropdown.
4. Select Add Role.
5. Confirm the role appears in the user's assigned role list.

## Removing a Role from a User

1. Open Settings, then select Users & Roles.
2. Select the user from the Users table.
3. In the Roles panel, find the role to remove.
4. Select Remove.
5. Confirm the user still has any other roles they need before leaving the page.

## Checking a Role Before Applying It

1. Open Settings, then select Users & Roles.
2. Select the role from the Roles table.
3. Review the role description, system name, type, permissions, and assigned users.
4. Return to the user record when you are ready to apply the role.

> Prefer assigning the least powerful role that lets the user do their work. Add more specific roles only when the user needs the extra workflow access.
